# Reviewed PostgreSQL v2

This is a retained synthetic example and an internal composition path, not live-source activation or production approval. Existing `cube-rest-v1` schemas, models and bundle hashes remain unchanged. Public REST, MCP and publisher request/result contracts are unchanged.

## Exact authority

The operator-owned `ReviewedCubeBinding` pins one data cube, a daily time dimension, exact-decimal measures, string dimensions, independent tenant and access-group members, and a hidden checkpoint member. No SQL, URL, credentials, policy or model enters through product queries. Model and security bytes have immutable bundle identities. `gateway.reviewed_runtime.load_assets()` checks the retained example against the source bytes and security contract before composition.

V2 polling requires the immutable `ExecutionSpec` and executed policy decision supplied by Worker or FixtureRunner. It rebuilds the exact expected Cube query from the accepted canonical request and compares canonical bytes before every poll. A schema-valid changed date, filter, sort or limit is rejected. The current policy is separately checked, with no positive authorization cache. The persisted PreparedQuery and database trigger are unchanged.

The actual shared Services container can be composed with `gateway.reviewed_runtime.build_runtime(registry=..., authenticator=..., secret_resolver=..., audit_key=..., cursor_key=..., assets=...)`. Dependencies and endpoint overrides are explicit trusted operator inputs. It does not provision, publish, create credentials or select a live source. The original demo and OIDC pilot entrypoints are unchanged.

## Correlated source freshness

The checkpoint is returned as a hidden STRING dimension in the same query and cached result as the data. PostgreSQL renders an explicit UTC RFC3339 instant, with microseconds, before Cube applies the user's data timezone. Offsetless timestamps are rejected; the adapter never guesses that a local string is UTC. Every nonempty row must carry the identical nonfuture checkpoint. Only that exact hidden member is stripped before ordinary normalization.

The source model joins each data row to exactly one checkpoint using its tenant key. The checkpoint relation must have an enforced unique tenant key; otherwise the join could multiply aggregate amounts even when timestamps match. The producer must atomically publish the data change and corresponding committed-load checkpoint in one transaction. The checkpoint describes the whole relevant tenant dataset, including its access groups. Neither metadata nor an operator-provided label proves those properties. Source-specific review and actual deployment evidence remain required.

The disposable example proves these prerequisites only for its initial seed transaction, not for an ongoing producer. Every later load must preserve the atomic publication contract. Its primary-keyed `demo_source.watermark` / `test_source.watermark` prevent join fanout. Consumer and fixture models read separate schemas with the existing separate read-only roles. Same-statement PostgreSQL snapshot semantics correlate the selected rows and joined checkpoint; a later checkpoint request cannot freshen an earlier result because no separate checkpoint request exists in v2. Refresh-key queries only affect cache invalidation and never become freshness evidence.

An empty result has no checkpoint evidence. Its freshness is unknown, and a product requiring freshness fails with `FRESHNESS_UNKNOWN`. Mixed, absent, offsetless, malformed or future checkpoints fail closed. Cached old checkpoints continue aging and fail `STALE_DATA` as appropriate. This example's publication fixtures include nonempty known answers, invalid input and permission denial; empty-result freshness is covered separately because existing publication fixture kinds cannot express a freshness-negative case.

## Deployment and limits

New assets live under `cube/reviewed-postgres`; `scripts/reviewed_cube_bundle_digest.py` covers config, security, security contract and the exact model file. Consumer and fixture bundles have distinct identities. The optional disposable harness may mount them into two additional private Cube services using the pinned existing image and separate consumer/fixture source roles/signing-key references. No new source credentials are generated by this module.

The retained query path preserves date, row, byte, deadline and scope limits. Read-only source roles, server statement timeouts and source reservation quarantine remain necessary. A successful row result is not a general proof that arbitrary background jobs have stopped; this Postgres example retains the existing source lifecycle assumptions and does not confer BigQuery completion semantics.

Before adapting a real mutable operational source: review the fixed model, exact numeric/time behavior, transaction/checkpoint producer, enforced uniqueness and tenant/group correlation; configure TLS and least-privilege relations; prove source bounds, permissions and revocation against the retained release. If atomic producer checkpoints cannot be established, use a separately reviewed immutable snapshot protocol or report unknown freshness. Do not substitute event recency, query time, an unrelated checkpoint service, or metadata inspection.
